## 快速开始

### 系统要求

- **操作系统**: macOS 10.15+, Linux, Windows 10+
- **浏览器**: Chrome 90+, Firefox 88+, Safari 14+, Edge 90+
- **Docker**: 20.10+ (推荐) 或本地环境

### 使用Docker启动（推荐）

```bash
# 1. 进入项目目录
cd /Users/apple/CornV2

# 2. 启动所有服务
docker-compose up -d

# 3. 等待服务启动（约30秒）
docker-compose ps

# 4. 访问系统
# 前端: http://localhost:3080
# 后端API: http://localhost:18000/api/health
```

详见 [开发者文档](DEVELOPER.md)

## 功能介绍

### 1. 仪表盘 (Dashboard)

**路径**: `/dashboard`

**功能**:
- 系统运行状态概览
- 实时数据统计
- 采集器运行状态
- 质量评分趋势图
- 最近采集记录

**关键指标**:
- 今日采集数量
- 数据质量分布
- 缓存命中率
- API响应时间

### 2. 采集器管理 (Collectors)

**路径**: `/collectors`

**功能**:
- 查看所有采集器列表
- 手动运行采集器
- 查看采集历史
- 采集器状态监控

**操作步骤**:

#### 运行采集器

1. 进入采集器管理页面
2. 选择要运行的采集器（如"博亚和讯"）
3. 点击"运行"按钮
4. 设置最大采集数量（可选，默认100条）
5. 点击"确认"开始采集
6. 查看实时进度

#### 查看采集历史

1. 点击采集器卡片的"历史"按钮
2. 查看历史运行记录
3. 可按时间、状态筛选
4. 查看每次运行的详细信息：
   - 开始时间
   - 结束时间
   - 采集数量
   - 成功/失败状态
   - 错误信息（如有）

### 3. 数据查询 (Data)

**路径**: `/data`

**功能**:
- 查询RAW层原始数据
- 查询STANDARD层标准化数据
- 多维度过滤（日期、指标、地区、来源）
- 数据导出（CSV、JSON）
- 数据血统追溯

**查询步骤**:

#### 基础查询

1. 选择数据层（RAW/STANDARD）
2. 设置日期范围（可选）
3. 选择指标（可选）
4. 选择地区（可选）
5. 点击"查询"

#### 高级过滤

1. 点击"高级过滤"
2. 设置质量等级（仅STANDARD层）
3. 选择数据源
4. 设置排序方式
5. 点击"应用过滤"

#### 数据血统追溯

1. 在数据列表中找到目标记录
2. 点击"血统"按钮
3. 查看完整的数据流向：
   - 原始采集URL
   - 采集时间
   - 采集器信息
   - HTML存档位置
   - 标准化时间
   - 质量评估结果

### 4. 质量监控 (Quality)

**路径**: `/quality`

**功能**:
- 数据质量总览
- 质量等级分布图
- 质量问题列表
- 质量趋势分析

**质量等级说明**:

| 等级 | 分数 | 说明 | 建议 |
|------|------|------|------|
| **A** | 90-100 | 优秀，官方数据，完整准确 | 可直接使用 |
| **B** | 80-89 | 良好，商业数据，基本可靠 | 推荐使用 |
| **C** | 70-79 | 及格，媒体数据，需验证 | 谨慎使用 |
| **D** | <70 | 不合格，数据有问题 | 不建议使用 |

**常见质量问题**:

1. **数据超时**: 超过72小时的数据
2. **缺少字段**: 地区、单位等信息缺失
3. **数值异常**: 超出合理范围
4. **来源不明**: 无法确定数据来源

### 5. 系统设置 (Settings)

**路径**: `/settings`

**功能**:
- 主题切换（深色/浅色）
- 缓存管理
- 系统参数配置
- 日志查看

**缓存管理**:

1. 查看缓存统计
   - 总键数
   - 内存使用
   - 命中率
   
2. 清除缓存
   - 清除全部缓存
   - 清除指定键

## 操作指南

### 日常操作流程

#### 每日数据采集

```
1. 访问仪表盘，检查系统状态
2. 进入采集器管理页面
3. 依次运行各采集器：
   - 博亚和讯（玉米现货）
   - 新浪财经（期货行情）
4. 查看采集进度和结果
5. 进入质量监控页面，检查数据质量
6. 如有质量问题，进行人工审核
```

#### 数据分析流程

```
1. 进入数据查询页面
2. 选择STANDARD层（已标准化）
3. 设置日期范围（如：最近30天）
4. 选择目标指标（如：山东玉米到车量）
5. 选择质量等级（推荐：A、B级）
6. 查询并导出数据
7. 使用Excel或其他工具进行分析
```

#### 问题排查流程

```
1. 发现数据异常
2. 在数据查询页面找到异常记录
3. 点击"血统"查看数据来源
4. 检查RAW层原始数据
5. 如需查看原始HTML，根据metadata中的html_path查找
6. 确认是采集问题还是源数据问题
7. 记录问题并反馈
```

## 常见问题

### Q1: 采集器运行失败怎么办？

**A**: 
1. 检查网络连接
2. 查看采集器状态（可能正在运行中）
3. 查看错误日志
4. 如果是源网站问题，等待后重试
5. 持续失败请联系管理员

### Q2: 为什么有些数据质量等级是D？

**A**: 
D级数据通常存在以下问题：
- 数据来源不可靠
- 缺少关键字段
- 数值超出合理范围
- 数据过时（>72小时）

建议：不要使用D级数据，或人工审核后使用。

### Q3: 如何导出数据？

**A**:
1. 在数据查询页面执行查询
2. 点击"导出"按钮
3. 选择格式（CSV或JSON）
4. 点击"下载"

### Q4: 缓存命中率低怎么办？

**A**:
缓存命中率低可能原因：
- 查询条件变化频繁
- 缓存刚清除
- 数据更新频繁

解决方案：
- 使用常见查询条件
- 避免频繁清除缓存
- 等待缓存预热（约10-20次请求后）

### Q5: 主题切换后样式错乱？

**A**:
1. 刷新页面（F5）
2. 清除浏览器缓存
3. 如仍有问题，联系技术支持

### Q6: 数据血统显示"无法追溯"？

**A**:
可能原因：
- RAW层数据已被清理
- 数据迁移时血统链断裂
- 手动插入的数据无血统

### Q7: 如何查看原始HTML？

**A**:
1. 查询STANDARD层数据
2. 点击"血统"按钮
3. 查看"HTML存档"字段中的路径
4. 联系管理员获取文件（需服务器访问权限）

## 故障排查

### 前端无法访问

**症状**: 浏览器显示"无法访问此网站"

**排查步骤**:
```bash
# 1. 检查前端服务是否运行
docker-compose ps frontend

# 2. 查看前端日志
docker-compose logs frontend

# 3. 检查端口占用
netstat -an | grep 3080

# 4. 重启前端服务
docker-compose restart frontend
```

### 后端API无响应

**症状**: 页面一直加载中，无数据显示

**排查步骤**:
```bash
# 1. 检查后端服务状态
curl http://localhost:18000/api/health

# 2. 查看后端日志
docker-compose logs backend

# 3. 检查数据库连接
docker-compose ps postgres

# 4. 重启后端服务
docker-compose restart backend
```

### 数据库连接失败

**症状**: 后端日志显示"数据库连接失败"

**排查步骤**:
```bash
# 1. 检查PostgreSQL是否运行
docker-compose ps postgres

# 2. 测试数据库连接
docker-compose exec postgres psql -U corn_user -d corn_research

# 3. 检查环境变量
cat .env | grep DATABASE

# 4. 重启数据库
docker-compose restart postgres
```

### Redis连接失败

**症状**: 缓存功能不可用，响应变慢

**排查步骤**:
```bash
# 1. 检查Redis是否运行
docker-compose ps redis

# 2. 测试Redis连接
docker-compose exec redis redis-cli ping

# 3. 检查Redis日志
docker-compose logs redis

# 4. 重启Redis
docker-compose restart redis
```

### 采集器运行失败

**症状**: 采集器状态显示"error"

**排查步骤**:
1. 查看采集器历史，找到错误信息
2. 检查目标网站是否可访问
3. 检查是否被限流（403/429错误）
4. 查看Python采集器日志
5. 尝试手动运行采集器脚本

```bash
# 手动运行采集器
cd collectors-python
python -m collectors.boyar_production
```

### 数据质量异常

**症状**: 大量D级数据，或数据缺失

**排查步骤**:
1. 查看质量问题列表
2. 检查是否是源数据问题
3. 检查质量评估逻辑是否需要调整
4. 查看数据血统，追溯到源头
5. 必要时重新采集

### 性能问题

**症状**: 页面加载慢，API响应超时

**排查步骤**:
```bash
# 1. 检查系统资源
docker stats

# 2. 查看缓存命中率
curl http://localhost:18000/api/cache/stats

# 3. 检查数据库查询性能
docker-compose exec postgres psql -U corn_user -d corn_research
# 然后执行: EXPLAIN ANALYZE SELECT ...

# 4. 清除缓存重建
curl -X POST http://localhost:18000/api/cache/clear

# 5. 重启所有服务
docker-compose restart
```

## 最佳实践

### 数据采集

1. **定时采集**: 建议每日固定时间采集（如：每天9:00、14:00）
2. **批量控制**: 单次采集不超过100条，避免限流
3. **错误重试**: 失败后等待5-10分钟再重试
4. **质量监控**: 每次采集后检查数据质量

### 数据查询

1. **使用过滤**: 尽量添加过滤条件，减少数据量
2. **选择合适的层**: 
   - 需要溯源：查询RAW层
   - 日常分析：查询STANDARD层
3. **质量筛选**: 分析时只使用A/B级数据
4. **分页查询**: 大量数据分批次查询

### 系统维护

1. **定期清理**: 每月清理过期的RAW层数据
2. **备份数据**: 每周备份数据库
3. **监控日志**: 定期查看错误日志
4. **性能优化**: 监控缓存命中率，保持>80%
